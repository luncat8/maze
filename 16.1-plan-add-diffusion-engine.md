## Context (unchanged from 16-plan, kept for self-containment)

`main` exposes four selectable engines via `magEngine` (`js/state.js`):

| Value         | Module                     | Notes |
|---------------|----------------------------|-------|
| `'diffusion'` | `js/magfield_diffusion.js` | **NEW** — transient forward-Euler cell-to-cell diffusion. Default. |
| `'tapered'`   | `js/electric.js` (inline)  | Analytic-tapered Biot–Savart, relaxed by red-black Gauss–Seidel. (was `'ar'`). |
| `'hy3'`       | `js/magBzPoissonHy3.js`    | Screened-Poisson `(∇²−λ²)Bz = S`, self-field cancellation. (file renamed). |
| `'direct'`    | `js/electric.js` (inline)  | Legacy per-frame Biot–Savart sum, hard `MAG_RMAX` cutoff. |

The new engine advances `∂Bz/∂t = α·∇²Bz + S` with an explicit forward-Euler
update, so the field *spreads cell-to-cell over successive frames* rather than
converging silently to a steady-state solution. This is the observable
"visual relaxation" the user asked for.

## Review findings → resolution

The external review (`15.5-review.txt`) raised seven findings, A–G, on the
16-plan. Three are already resolved in the tree; four remain and are the
substance of this plan.

### Already resolved (do not redo)

- **C — α = 0.25 is exactly marginal.** The amplification factor at the
  Nyquist mode is `g = 1 − 8α`, so `α = 0.25` gives `g = −1`: a neutrally
  stable checkerboard that never damps. Resolved: slider cap is **0.24**
  (`g = −0.92`) in `js/ui.js` (`slider.max = 0.24`), and the reason is written
  into the headers of `js/electric.js`, `js/state.js`, and
  `js/magfield_diffusion.js`.
- **D — clamp mutated the user's global.** `magDiffusionRelax` now uses a
  **local** `const alpha = Math.min(MAG_DIFFUSION_ALPHA, 0.24)` and warns
  without writing back, so the slider readout never desyncs from the live
  value.
- **G — identical `if (e.dlx === 1) … else …` branches.** Collapsed in both
  `magDiffusionBuildSource` and `magBzPoissonHy3BuildSource` to a single
  signed-incidence assignment with one comment block. (The old
  "horizontal vs vertical" labels were physically misleading: the ±I split is
  identical by construction.)

### Remaining — the work of this plan

- **A — the headline test (old 11b) proves nothing.** The implemented update
  `nv = bz + α·(Σ−4·bz) + S` has steady state `α·∇²Bz + S = 0`, i.e.
  `∇²Bz = −S/α`, so the settled amplitude scales as **1/α**. The smoke numbers
  the old plan quoted — peak 23.09 at α=0.05 vs 5.78 at α=0.20, ratio 3.994
  ≈ 4 = 0.20/0.05 — are exactly the 1/α Poisson factor, not transient decay.
  An instant Poisson solve produces *the same two peaks*. **The old 11b cannot
  distinguish transient from steady-state.** → T2 replaces it.
- **B — `S` is added on every sweep with no `dt`, so α does double duty.**
  Settled `peak ∝ K_B/α`, independent of sweep count; `MAG_SWEEPS_PER_FRAME`
  only changes the *lag*, while α changes both speed **and** force amplitude
  (≈ 12× across the 0.02–0.24 slider). There is no `MAG_SRC_GAIN_DIFF` (Hy3
  has `MAG_SRC_GAIN_HY3 = 20`; the diffusion engine scales by `K_B` alone, so
  its field is ~20× weaker than Hy3 at the same `K_B`). → T1 fixes it.
- **E — no dipole support.** `magDiffusionBuildSource` has no dipole injection
  and no self-force subtraction, and Task 8 hides `#magDipoles` under
  `diffusion`. With `MAG_DIPOLES` on, switching to `diffusion` silently drops
  the magnet↔magnet interaction. → T3 decides and documents.
- **F — the publish block is duplicated verbatim.** `magDiffusionPublish` is
  `magBzPoissonHy3Publish` minus the `needSelf` block, plus a `fieldBz` copy.
  Both compute `Eb`/`elecP`/`lastEMF`/`lastHeat` while **neither** injects
  back-EMF, and both are O(M·E). → T4 extracts one shared helper.

## Remaining tasks (ordered)

### T1 — Source formulation: decouple α from settled amplitude (finding B)

**LANDED — with one correction to the step-3 formula.** The plan's literal
`nv = bz + alpha * (lap + magSrcDiff[i])` has settled state `lap + S₀ = 0`,
i.e. `∇²Bz = −S₀`, while Hy3 (whose source construction this engine copies
byte-for-byte) solves `∇²Bz = +S`. Measured before the fix: on the rail
scene the two engines' `fieldBz` peaks had **opposite signs**
(diffusion −5.78 vs Hy3 +22.82), so `m.lastFcoil` flipped sign on an engine
switch — exactly what T2's 11c and T6's 5d are supposed to pin. The landed
form is therefore

```js
const nv = bz + alpha * (sum - 4 * bz - magSrcDiff[i]);   // ∂Bz/∂t = α·(∇²Bz − S₀)
```

which settles onto `∇²Bz = +S₀` — the same equation sign as Hy3 at λ=0.
Everything else is as specified: `MAG_SRC_GAIN_DIFF = 20`, source folded
inside the α bracket, local clamp kept. Verified: tapered/hy3/diffusion
all push the same way on the L-loop scene (5d) and on the rail scene at
an off-centre magnet placement (11c).

`js/magfield_diffusion.js`, `js/state.js`.

1. Add `let MAG_SRC_GAIN_DIFF = 20;` to `js/state.js` beside
   `MAG_LAMBDA`/`MAG_DIPOLES`, with a comment mirroring
   `MAG_SRC_GAIN_HY3`'s ("Stokes curl source on the unit grid is ~20× smaller
   than the tapered windowed sum; scale so the field is in the same ballpark
   at the same `K_B`").
2. In `magDiffusionBuildSource`, change the trailing scale loop from
   `magSrcDiff[i] *= K_B` to `magSrcDiff[i] *= K_B * MAG_SRC_GAIN_DIFF`.
3. In `magDiffusionRelax`, fold the source **inside** the α-scaled bracket:

   ```js
   const lap = sum - 4 * bz;
   const nv = bz + alpha * (lap + magSrcDiff[i]);
   ```

   Steady state becomes `lap + S₀ = 0`, i.e. `∇²Bz = −S₀`, with
   `S₀ = K_B·MAG_SRC_GAIN_DIFF·curlJ` — **α-independent**. α now controls only
   the relaxation time constant (`t_eff ≈ α·sweeps` per frame); the settled
   field no longer rescales 12× across the slider. This is the "dt" separation
   the critique asked for, in the simplest form: the per-step source increment
   is `α·S₀`, so α is the single speed knob and amplitude is decoupled.

4. Keep the local `alpha ≤ 0.24` clamp/warn. No other site changes.

**Why it can't regress:** for `MAG_SRC_GAIN_DIFF = 20` and `α` near the default
0.20 the settled field changes (that's the point), but the *sign convention* is
untouched, so `m.lastFcoil` keeps its sign across engine switches. The round-
trip test (T2's 11c) guards sign and finiteness.

### T2 — Transient test that actually discriminates (finding A)

**LANDED** (16 assertions, `test_magdiff` test 11 — plus 17-T3's 11d).
Two notes for anyone re-running the numbers:

1. **The circuit must be converged first.** `e.I` is written by
   `fieldPublish`, and the electric solve is itself a relaxation, so
   measuring the Bz transient on a cold circuit measures the *current*
   transient instead. Same scene, same 500-sweep Bz budget, varying only
   the settle frames: peak `|Bz|` = 175 (1 frame), 23.9 (20), 23.08 (40).
   Both 11a and 11b therefore settle 40 frames with the magnet pinned.
2. **11c's magnet cannot sit at the centred (15,15)/(20,15) cells.** There
   the analytic gradient is a small residue of large cancelling terms and
   the 1-cell grid gradient genuinely gets the sign wrong — that is what
   test 12 exists to document (tapered +8.86e-1 vs hy3/diffusion −9.0e-3 /
   −2.0e-2 at (20,15)). The landing test uses the off-centre (12,14),
   where measured tapered/hy3/diffusion are −2.44e-1 / −1.00e-1 /
   −1.21e-1 and all three agree; the tapered-vs-diffusion sign contract in
   a *degenerate* geometry is pinned by `test_solenoid` 5d (L-loop)
   instead.


`js/test_magdiff.js`. The old plan's "Test 11" (diffusion block) was never
written; the existing Test 11 is "Grid owns values, analytic kernel owns
derivatives". Insert the new diffusion block **between Test 10 and the existing
Test 11** and renumber the existing Test 11 → **Test 12**. (Renumbering is the
least disruptive: the existing block is self-contained and cites no
neighbouring numbers.)

Reuse the existing helpers `clearBoard()`, `railScene()`, `step()`, `getRef()`.
`clearBoard()` already sets `magEngine = 'tapered'`, so each subtest sets
`magEngine = 'diffusion'` explicitly (mirror Test 10a).

**11a — transient discrimination (the real proof).** Rail scene,
`magEngine='diffusion'`, fixed `MAG_DIFFUSION_ALPHA = 0.20`, `magReset()`.
Advance the field three times with **the same α** but different sweep budgets
and record the peak `|fieldBz|` each time:

```js
function peakAt(sweeps) {
  magDiffusionReset();
  magDiffusionBuildSource();
  magDiffusionRelax(sweeps);     // sweep budget is the only variable
  magDiffusionPublish(pistons);
  // max |fieldBz| over the grid
}
peak(5) < peak(50) < peak(500)   // monotone toward the asymptote
```

An instant Poisson solve would return the same peak for all three budgets;
only a genuinely transient engine grows with the advance count. Assert strict
monotonicity (with a small absolute tolerance, e.g. each gap > 1e-3) and that
`peak(500)/peak(50)` is approaching 1 (settling, not diverging).

**11b — α-independence of the *settled* amplitude (T1's contract).** Same
scene, budget fixed at "enough to settle" (500 sweeps), α ∈ {0.05, 0.20}.
After T1 the settled peak is α-independent, so assert the two peaks agree to
within a few percent (e.g. `< 10%`), while the *transient* peak at 5 sweeps
differs by α (it takes ~1/α longer to build). This is the inverse of the old
(wrong) 11b and directly checks T1.

**11c — round-trip.** `magEngine = 'tapered'; magReset(); fieldSimulate();`
produces a finite `lastFcoil` with the same sign as the diffusion run; the
diffusion buffers don't leak into `tapered`.

### T3 — Dipole decision (finding E)

**LANDED.** Implemented as decided: hidden toggle + honesty. Concretely
`magEngineOnChange` now logs a `warn` line when `'diffusion'` is selected
while `MAG_DIPOLES` is on ("your setting is kept and comes back under
Hy3"), the engine note element `#magEngineNote` shows the caveat in the
panel, and the same wording is in `docs/magnetic-engines.md` and in the
`js/magfield_diffusion.js` header.

**Bonus bug found while wiring this up.** The show/hide logic never
worked: an author rule (`.ctrl { display: flex }`) beats the UA
`[hidden] { display: none }` rule in the cascade, so `magEmitAllLbl.hidden
= true` did nothing, and `#magDipolesLbl` carried an inline
`style="display:none"` that `hidden = false` cannot undo. Net effect in a
real browser: "Magnets emit B" was always visible and "Magnets inject
dipoles" was never visible, on every engine. Fixed with
`[hidden] { display: none !important; }` plus dropping the inline style
(both labels now start `hidden`, matching the `'diffusion'` default).


**Decision: document as a known limitation + a visible UI hint in this plan;
implement a dipole injector in Phase 2.** Rationale: diffusion is field-only
(no back-EMF) by design in this phase, and a correct dipole injector needs the
self-subtraction machinery Hy3 carries (`magSrcSelfHy3`/`magBzSelfHy3` +
`MAG_SWEEPS`-scale convergence), which is real scope. Hiding the toggle while
silently changing the force law is the bug — fix the *honesty*, not the math.

Concretely: in `js/ui.js` the `diffusion` arm of `magEngineOnChange` keeps
`#magDipoles` hidden; add a one-line hint (e.g. a small note in the
`#magDipolesLbl` text or a `logger` line on engine change) stating "dipoles are
not supported under diffusion — magnet↔magnet interaction is off". Add the same
caveat to `docs/magnetic-engines.md`. Phase 2 option is recorded under "Out of
scope" so it isn't lost.

### T4 — Extract shared publish telemetry (finding F)

**LANDED.** `magPublishTelemetry(mags, bzAt, opts)` lives in
`js/electric.js` rather than in `js/magBzPoissonHy3.js` (the plan allowed
either): electric.js is the module *both* engines already depend on
(`magnetList`, `edgeIsSelf`, `isCaseA`, `bodyHat`, `bodyCenter`,
`fieldEdges`, and 2 of the 4 engines), it loads first, and it avoids
making the diffusion engine call into Hy3's file or adding a new script
tag to `index.html` + five test harnesses. Hy3 passes
`opts.selfGrad = hy3SelfGrad` (its own dipole self-field solve, moved out
of the loop body); diffusion passes nothing. Output is byte-identical to
the two bodies it replaces — verified by the unchanged assertion counts of
all five suites before the new tests were added.


New helper in `js/magBzPoissonHy3.js` (or a small shared module), exported and
used by both engines:

```js
function magPublishTelemetry(mags, bzAt, opts) { /* the shared ~40 lines */ }
```

`magDiffusionPublish` and `magBzPoissonHy3Publish` become thin wrappers:
diffusion calls it with `opts.selfSubtract = false` (plus its `fieldBz` copy
loop); Hy3 calls it with `opts.selfSubtract = MAG_DIPOLES && mags.length` (and
does the self-field solve before delegating). The shared body owns `Eb`,
`elecP`, `lastEMF`, `lastHeat`, `lastBz`, `lastFcoil`, `lastCurrent`, and the
per-magnet O(E) armature/bridge-current scan.

This also retires two deferred 15.5 items at once (the duplicate publish block
and the "EMF telemetry under field-only engines" note), and gives one place to
later add back-EMF or a residual gate.

## Risks

- **T1 changes the diffusion field's magnitude** (gain 20, α folded in). This
  is intended; the sign convention is untouched, so cross-engine force sign is
  preserved. Re-run the full suite before/after.
- **Renumbering existing Test 11 → 12** touches only that block's header line
  and the one `console.log`. Nothing else references the number.
- **T4 refactor** is the riskiest mechanical change; mitigate by keeping the
  shared helper's output byte-identical to the current two publish bodies, then
  deleting the duplicates. Test 10a/b/c and 11c guard telemetry correctness.
